# Агент тарифных кампаний Beeline

`agent.py`: портфель экспертов (история + LLM) предлагает гипотезы → адаптивные пилоты → жадный план под лимиты. pandas/numpy + stdlib. Без LLM-ключа (`OPENROUTER_API_KEY` / `OPENAI_API_KEY`) детерминирован.

## Ключевое наблюдение
Эффект кампании зависит только от **ячейки** `(current_tariff, arpu_segment)`, целевого тарифа и канала. Канал лишь умножает эффект (`ratio = pct × conv × mult`). Отсюда:
- гипотеза — это `ячейка × target`: всего 63 ячейки, фильтры data/call на эффект не влияют;
- один пилот через SMS даёт оценку сразу для всех каналов: `base = observed / 0.65`;
- стоимость контакта мала по сравнению с приростом, поэтому результат ограничивают охват и бюджет, а не окупаемость.

## Как работает
1. **Prior.** Из `data/change_tariff.csv` для каждой тройки (from, seg, to) считаем `base = средний Δ% ARPU × доля переходов`. Среднее сжимается к 0 при малом числе наблюдений. Стандартное отклонение prior намеренно широкое (0.25): история — это другая выборка.
2. **Рукава — портфель экспертов.** Эксперты предлагают рукава `(ячейка, target)` в общий реестр. У каждого рукава гауссов апостериор (μ, σ²) и `src` — кто его предложил.
   - **prior:** 4 лучших target по истории.
   - **llm:** один вызов OpenAI-совместимого API (stdlib `urllib`, timeout 60 с): есть `OPENROUTER_API_KEY` → OpenRouter, модель из `LLM_MODEL` или селектора в Cockpit; иначе OpenAI по `OPENAI_API_KEY`/`OPENAI_MODEL`. Получает таблицы тарифов и ячеек, возвращает до 2 target на ячейку с оценкой эффекта. Невалидные тарифы и ячейки отбрасываются, оценка клипуется в ±0.5. Сбой или нет ключа → эксперт молча выключается.
   - Если рукав предложили оба, μ берётся из истории.
   - Мета-выбор между экспертами делает сам EI из шага 3: пилот достаётся лучшему *рукаву*, а не лучшему *эксперту*. Thompson поверх экспертов не делали: 20 пилотов — это ~5 на эксперта, веса отражали бы шум. Плохой LLM-рукав просто не пройдёт LCB после пилота.
   - Гипотеза, которую предложил только LLM, попадает в план лишь после пилота. Без этого правила непилотированные догадки модели (≥ 0.125) проходили LCB, и LLM ухудшал результат на всех 10 стресс-мирах: медиана 5.96M против 6.79M.
   - В лог по каждому эксперту пишутся: число рукавов, пилоты на его рукавах, средний obs, hit rate, сколько его рукавов попало в план.
3. **Адаптивные пилоты.** Следующим пилотируем рукав с максимальным *expected improvement* × Σ ARPU ячейки. Размер пилота масштабируется с размером ячейки (60–200 абонентов).
   - Апостериор обновляется байесовски: шум `0.804/√n` из документации среды. Поэтому пилот на 200 абонентах весит больше пилота на 60.
   - Разведка останавливается, когда кончились пилоты или EI упал ниже 0.5% от стартового, либо сработал резерв бюджета.
4. **План.**
   - В каждой ячейке берём лучший target. Ячейка идёт в план, если `μ − 0.5σ > 0`.
   - Ячейки заполняют охват по убыванию ценности на контакт.
   - Канал: все ячейки стартуют с push, затем жадно апгрейдятся по Δnet/Δcost, пока хватает бюджета. Так дорогие каналы достаются самым ценным сегментам.
   - Ячейки группируются в ≤10 кампаний `arpu × "tA;tB" → target, channel`, не больше 5000 абонентов в каждой.
5. **Fallback.** Любая ошибка или пустой план → одна кампания, а не падение и не пустой ответ (ТЗ требует ≥1): sms по лучшему рукаву, если он проходит LCB, иначе бесплатный push на наименее убыточную ячейку. `stress_eval.py` проверяет это в мире «нет `data/`, все эффекты отрицательные».

## Что показали данные
- **История ≠ аудитория.** Общих ID нет.
  - В аудитории 59% HIGH-абонентов, в истории 35%. Медиана ARPU 5930 против 3700.
  - Самые ценные тарифы в аудитории встречаются в истории заметно реже: tariff_8 — 30% против 14%, tariff_14 — 8% против 2%.
  - HIGH в истории в среднем даёт downsell (медиана Δ% = −0.12), LOW — upsell (+0.79). Prior по HIGH пессимистичен, но именно там основная ценность. Поэтому пилоты выбираются по EI × Σ ARPU, а не по prior.
- **Prior внутренне стабилен.** Split-half корреляция средних по переходам (from, seg, to) — 0.84. Без истории остаются только 3 из 63 ячеек (0.1% ARPU). Слабое место prior — перенос на другую выборку, а не шум, поэтому ширина prior 0.25.
- **Поправка prior по трафику (`USE_FIT`).** `traffic.csv` описывает только абонентов из истории, с аудиторией пересечения нет. Трафик снят за апрель–сентябрь, переходы — в октябре, так что утечки будущего нет.
  - Агент считает долю абонентов, чей трафик влезает в пакет target, отдельно в истории и в аудитории ячейки. Prior сдвигается на β × разницу этих долей.
  - Наивно «влезает → upsell» даёт β = 0.38. Но внутри одного перехода (from, seg, to) β = 0.023, 95% ДИ [−0.02; 0.06]. Разница объясняется тем, *какие* переходы популярны, а не тем, как трафик ложится в пакет.
  - Сравнение на 10 нейтральных мирах и 10 мирах, где эффект fit заложен (β = 0.25): с честным β = 0.023 план идентичен варианту без поправки. Наивный β = 0.25 даёт +2% медианы — в пределах шума, в нейтральных мирах минимум хуже.
  - Поправка включена: она выводится из данных и ничего не ломает, но на решения сейчас не влияет. `arpu_monthly.csv` не используется: ARPU аудитории уже есть в `predicted_arpu`.
- **Честная игра.** `agent.py` импортирует только math/pathlib/numpy/pandas. Из env он использует только публичные атрибуты и `run_pilot`, с диска читает только `data/change_tariff.csv` и `data/traffic.csv`. LLM и ключей нет. `stress_eval.py` — локальный стенд: строит среду через публичный `make_environment` со своими искажёнными эффектами и в сдачу не входит.

## Проверка
Все команды запускаются из корня репо: пакет организаторов лежит рядом с нашими файлами (в git не коммитится).
```bash
python local_eval.py --runs 10   # мок: 10/10 прогонов в плюс, net ≈ 4.2–4.7M
python stress_eval.py            # искажённые миры: сравнение с шаблоном, prior-only и оракулом
python make_submission.py        # воспроизводимый submission.csv
```
`stress_eval.py` искажает эффекты мока (pct × U(0.5, 2) + N(0, 0.3)), имитируя судейскую среду. Медиана по 10 мирам: агент 6.8M, шаблон 0.6M, prior-only 5.8M, оракул 11.1M. Проверены и отброшены (хуже минимум на стресс-мирах при той же медиане):
- калибровка prior общим сдвигом «пилот − prior»: медиана 6.75M, минимум 3.4M против 3.7M;
- 3 последних пилота на перепроверку крупнейшей неуверенной ставки (против winner's curse): минимум 2.9M;
- эксперт-эвристика «upsell на самый дешёвый тариф не дешевле текущего, чей пакет вмещает медианный трафик ячейки», 2 рукава на ячейку с μ = 0: медиана 6.93M против 6.79M, минимум 3.53M против 3.72M (лучше на 3 мирах, хуже на 4). Лишние рукава размывают пилоты, поэтому эксперт удалён.

Ablation экспертов, реальный LLM (`gpt-4o-mini`, один ответ на все seed), 10 стресс-миров:

| | медиана | минимум |
|---|---|---|
| prior + llm (`agent`) | 7.14M | 3.18M |
| только prior (`exp_prior`) | 6.79M | 3.72M |

LLM лучше на 3 мирах, хуже на 5, на 2 без разницы; суммарно около +1%, то есть на уровне шума. На моке (`local_eval`, 3 seed) LLM хуже на 3–6%: там история в точности совпадает с эффектами, и любой пилот, ушедший с prior-гипотез, стоит денег. LLM оставлен, потому что на судействе эффекты другие и история там менее надёжна. Без ключа `agent` совпадает с `exp_prior`. `check_llm` подменяет вызов API и проверяет две вещи: мусорные предложения LLM отсеиваются, падение API не ломает план.

Коэффициент `0.5σ` выбран на таких мирах и на пессимистичных (эффекты хуже истории): при `0σ` агент там уходит в минус, при `1σ` слишком осторожен.

## UI: Campaign Cockpit
Веб-интерфейс, в котором видно, что агент делает и почему. `server.py` (FastAPI) запускает агента в мок- или стресс-мире и отдаёт его внутреннее состояние: prior и posterior рукавов, пилоты, план, скоринг. `agent.py` при этом не меняется. `web/` — React 19 + HeroUI v3 + Vite 8.

```bash
pip install fastapi uvicorn             # только для UI, в сдачу не входит
uvicorn server:app --port 8000          # из корня репо; OPENROUTER_API_KEY / LLM_MODEL (или OPENAI_API_KEY) берутся из .env
cd web && npm i && npm run dev          # http://localhost:5173, /api проксируется на :8000
```

Экраны повторяют конвейер агента (1 Аудитория → 2 Гипотезы → 3 Пилоты → 4 Финальный план), плюс Командный центр, Стратегии (вклад экспертов и ablation на стресс-мирах), Privacy (что видит LLM, prompt inspector) и Логи. В «Пилотах» есть пошаговый replay разведки. Экран можно открыть по ссылке `#hypotheses`, `#plan` и т. п. `python3 server.py` — self-check API без запуска сервера.

## Лаборатория версий (`lab.py`)
Цикл самоулучшения поверх агента. В сдачу не входит, состояние хранится в `lab/` (в git не коммитится).

- **Версия** — набор настроек из allowlist `PATCH_TARGETS` поверх `agent.py`: константы (`LCB_K`, `PRIOR_STD`, размер пилотов…), флаги эвристик, режим privacy и `LLM_PROMPT_EXTRA`. Сам код не копируется. У версии есть `parent_id`, `commit_hash`, `prompt_hash`, `config_hash`, diff от родителя и статус `draft → candidate | failed → promoted`.
- **Матрица тестов** на каждую версию:
  - `local_eval` на 1 и 10 seed;
  - `stress_eval` на 10 миров;
  - жёсткие миры (`stress_eval.harsh_world`): эффекты перемешаны между переходами, `keep` — сколько правды осталось в истории. На `keep=0` (30 миров) стратегия без пилотов получает ~1/16 оракула — так в описании кейса выглядит судейская среда. На `keep=0.5` — 10 миров. В обычных стресс-мирах без пилотов получается около половины оракула: история там почти верна;
  - валидация кампаний;
  - бюджет и охват;
  - время прогона;
  - прогон с выключенным LLM;
  - сбой и мусор LLM (`check_llm` + `check_never_empty`).

  Около 10 с на версию: прогоны идут параллельно в процессах.
- **Детекторы** находят проблемы с доказательствами. Например, `HIGH_VARIANCE_BETWEEN_SEEDS` («медиана +6.8M, но 4/10 миров в минусе») или `WEAK_LLM_CONTRIBUTION` («рукава LLM добавлены, но ни один не попал в план»). Полный список — в `detect()`.
- **Ремедиация.**
  - Issues превращаются в ограниченный патч: либо LLM через тот же privacy gateway (в контексте только issues, метрики и границы настроек), либо шаблон.
  - Получается новая версия, она проходит ту же матрицу.
  - **Gate**: все must-have тесты пройдены; медиана жёстких миров `keep=0` не упала; медиана `keep=0.5` и стресс-миров упала не больше чем на 3%; худший мир `keep=0` не стал хуже (раньше — «прогонов в минусе не больше»: на границе нуля это монетка); 0 отброшенных кампаний. Если родитель оценён старой матрицей, он сначала перепрогоняется.
  - Ответы LLM кэшируются на диске по хэшу промпта (`lab/llm_cache/`). Иначе gate сравнивал бы шум модели: один и тот же конфиг давал 6.57M и 7.06M в двух прогонах.
- **Promote** — только кнопкой и только из `candidate`: константы переписываются в `agent.py` построчно, `submission.csv` пересобирается без ключа. Коммит — вручную.
- **Новые эвристики в `agent.py`** выключены по умолчанию, при них план совпадает с `submission.csv`:
  - `PILOT_SIZING="adaptive"`;
  - `RANK_BY="lcb"`;
  - `CHANNEL_MU="lcb"` + `UPGRADE_MIN_ROI`;
  - `META_CONTROLLER`;
  - `PILOT_BUDGET_SHARE`.

  Включает их только версия, прошедшая gate.
- **Privacy gateway** (`safe_context` → `llm_proxy` → `_parse_llm`):
  - в LLM уходят только ячейки и медианы полей `LLM_FIELDS`;
  - ячейки меньше `K_MIN` идут без статистик;
  - поле вне allowlist блокирует запрос;
  - каждый вызов пишется в аудит;
  - режимы: `aggregate_only`, `synthetic_only` (шум, округлённые n), `debug_safe` (ни одного числа об абонентах).

Первые замеры, 10 стресс-миров, живой `gpt-4o-mini`:

| версия | медиана | gate |
|---|---|---|
| baseline, промпт через gateway | 6.57M | — |
| baseline, прежний промпт (таблица выше) | 7.14M | — |
| `RANK_BY=lcb` | 6.95M | пройден |
| `CHANNEL_MU=lcb`, `UPGRADE_MIN_ROI=1` (предложил LLM) | 6.24M | отклонён |

Разница между двумя промптами — один ответ LLM на прогон, то есть в пределах шума. Без ключа baseline совпадает с `exp_prior` (6.79M).

```bash
python3 lab.py                          # self-check: validate, детекторы, gate, round-trip констант, быстрая матрица
```
