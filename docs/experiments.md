# Данные, эксперименты и отброшенные идеи

Как проверялся агент и почему он устроен именно так. Команды для воспроизведения — [testing.md](testing.md).

## Что показали данные
- **История ≠ аудитория.** Общих ID нет.
  - В аудитории 59% HIGH-абонентов, в истории 35%. Медиана ARPU 5930 против 3700.
  - Самые ценные тарифы в аудитории встречаются в истории заметно реже: tariff_8 — 30% против 14%, tariff_14 — 8% против 2%.
  - HIGH в истории в среднем даёт downsell (медиана Δ% = −0.12), LOW — upsell (+0.79). Prior по HIGH пессимистичен, но именно там основная ценность. Поэтому пилоты выбираются по EI × Σ ARPU, а не по prior.
- **Prior внутренне стабилен.** Split-half корреляция средних по переходам (from, seg, to) — 0.84. Без истории остаются только 3 из 63 ячеек (0.1% ARPU). Слабое место prior — перенос на другую выборку, а не шум, поэтому ширина prior 0.25.

### Поправка prior по трафику (`USE_FIT`)
`traffic.csv` описывает только абонентов из истории, с аудиторией пересечения нет. Трафик снят за апрель–сентябрь, переходы — в октябре, так что утечки будущего нет.
- Агент считает долю абонентов, чей трафик влезает в пакет target, отдельно в истории и в аудитории ячейки. Prior сдвигается на β × разницу этих долей.
- Наивно «влезает → upsell» даёт β = 0.38. Но внутри одного перехода (from, seg, to) β = 0.023, 95% ДИ [−0.02; 0.06]. Разница объясняется тем, *какие* переходы популярны, а не тем, как трафик ложится в пакет.
- Сравнение на 10 нейтральных мирах и 10 мирах, где эффект fit заложен (β = 0.25): с честным β = 0.023 план идентичен варианту без поправки. Наивный β = 0.25 даёт +2% медианы — в пределах шума, в нейтральных мирах минимум хуже.
- Поправка включена: она выводится из данных и ничего не ломает, но на решения сейчас не влияет. `arpu_monthly.csv` не используется: ARPU аудитории уже есть в `predicted_arpu`.

### CatBoost-prior не прошёл gate
По строкам модель точнее группового среднего, но внутри ячейки target выбирает не лучше, а на жёстких и стресс-мирах план хуже (`keep=0`: 3.91M у `hist` против 0.95–1.98M). Замеры и разбор причин — [catboost.md](catboost.md#результаты-почему-выключен).

## Стресс-миры
`stress_eval.py` искажает эффекты мока (pct × U(0.5, 2) + N(0, 0.3)), имитируя судейскую среду. Медиана по 10 мирам: агент 6.8M, шаблон 0.6M, prior-only 5.8M, оракул 11.1M.

## Проверены и отброшены
Хуже минимум на стресс-мирах при той же медиане:
- калибровка prior общим сдвигом «пилот − prior»: медиана 6.75M, минимум 3.4M против 3.7M;
- 3 последних пилота на перепроверку крупнейшей неуверенной ставки (против winner's curse): минимум 2.9M;
- эксперт-эвристика «upsell на самый дешёвый тариф не дешевле текущего, чей пакет вмещает медианный трафик ячейки», 2 рукава на ячейку с μ = 0: медиана 6.93M против 6.79M, минимум 3.53M против 3.72M (лучше на 3 мирах, хуже на 4). Лишние рукава размывают пилоты, поэтому эксперт удалён.
- частичный пулинг пилотов по target или сегменту (эмпирический Байес: сдвиг непилотированным рукавам с весом τ²/(τ²+σ²/n), τ² по методу моментов). Проверяли и на `--struct` — мирах, где история ошибается системно: общий сдвиг на target (sd 0.2) и сегмент. Итог 0 изменений на 28 из 30 миров: при 20 пилотах и ошибке prior 0.25 на рукав оценка τ² почти всегда 0, структуру такого масштаба не видно. Агент на `--struct`: медиана 5.8M, оракул 10.1M;
- EI как ценность информации (`EI − max(μ − best, 0)`), чтобы не пилотировать уверенного лидера повторно: медиана хуже на 3 из 4 типов миров (`world` 6.08M против 6.79M), лучше только на `keep=0`. Повторные пилоты лидера крупнейшей ячейки окупаются сами: пилотные контакты тоже идут в зачёт.

## Ablation экспертов
Реальный LLM (`gpt-4o-mini`, один ответ на все seed), 10 стресс-миров:

| | медиана | минимум |
|---|---|---|
| prior + llm (`agent`) | 7.14M | 3.18M |
| только prior (`exp_prior`) | 6.79M | 3.72M |

LLM лучше на 3 мирах, хуже на 5, на 2 без разницы; суммарно около +1%, то есть на уровне шума. На моке (`local_eval`, 3 seed) LLM хуже на 3–6%: там история в точности совпадает с эффектами, и любой пилот, ушедший с prior-гипотез, стоит денег. LLM оставлен, потому что в боевой среде эффекты другие и история там менее надёжна. Без ключа `agent` совпадает с `exp_prior`. `check_llm` подменяет вызов API и проверяет две вещи: мусорные предложения LLM отсеиваются, падение API не ломает план.

## Коэффициент LCB
`0.5σ` выбран на таких мирах и на пессимистичных (эффекты хуже истории): при `0σ` агент там уходит в минус, при `1σ` слишком осторожен.
