# Безопасность кокпита

Как устроена защита API и UI (`server.py`, `auth.py`, `datasets.py`, `lab.py`, `agent.py`), что проверяет
`security_check.py` и что нужно сделать перед выкладкой. Сам агент (`agent.py` + `submission.csv`) от этого
не зависит: сервер, БД и вход нужны только кокпиту.

## Кратко

| Слой | Как защищено | Где |
|---|---|---|
| Вход | fastapi-users, cookie `session` (HttpOnly, SameSite=Lax), токен в Postgres, logout его отзывает | `auth.py` |
| Перебор паролей | 10 неудачных входов с IP за 5 минут → 429 | `server.py` → `guard` |
| Роли | `manager` < `analyst` < `admin`, проверка на каждом маршруте до выполнения | `auth.require`, `server.py` |
| Демо-пароли | `<роль>@cockpit.demo` / `<роль>` заводятся только при `AUTH_DEMO=1` | `auth.bootstrap` |
| Загрузка CSV | whitelist видов, лимит 50 МБ, валидация колонок/значений до записи | `datasets.validate` |
| LLM | privacy gateway: в промпт только агрегаты из allowlist, ответ строго валидируется | `agent.llm_proxy`, `_parse_llm` |
| Лаборатория | правки только разрешённых констант с границами, запись в `agent.py` литералом | `lab.validate`, `set_constants` |
| Браузер | `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, React без сырого HTML | `server.py` → `guard` |
| Инфраструктура | Postgres слушает только `127.0.0.1`, `.env` не попадает в git и образ | `docker-compose.yml`, `.dockerignore` |

## Вход и сессии

- `POST /api/auth/login` (форма `username`=email, `password`) → 204 и cookie `session`. В cookie только случайный
  токен, сами сессии лежат в таблице `accesstoken` (`DatabaseStrategy`, срок 7 дней). `POST /api/auth/logout`
  удаляет токен: старый cookie сразу даёт 401.
- Пароли хэшируются `PasswordHelper` fastapi-users. Неизвестный email и неверный пароль дают одинаковый ответ 400,
  так что по ответу нельзя узнать, есть ли такой пользователь.
- **Лимит перебора.** Middleware `guard` считает ответы 400 на `/api/auth/login` по IP клиента. После 10 неудач за
  5 минут следующие попытки получают 429 без проверки пароля. Счётчик живёт в памяти процесса (см. ограничения ниже).
- **Нельзя повысить себе роль.** Роутер `/users` fastapi-users не подключён, в `UserRead` роль только на чтение.
  Роль меняется лишь из консоли: `python3 auth.py add <email> <пароль> <роль>`.
- **Первый запуск.** При пустой таблице пользователей `auth.bootstrap` заводит их из
  `AUTH_USERS="email:пароль:роль,..."`. Если переменной нет, демо-набор заводится только при `AUTH_DEMO=1`
  (так по умолчанию в `docker compose`, чтобы работал быстрый старт из README). Без обеих переменных сервер не
  стартует: случайно выложить стенд с паролем `admin` нельзя.

## Роли и доступ

| Маршрут | manager | analyst | admin |
|---|---|---|---|
| `GET /api/me` | ✓ | ✓ | ✓ |
| `GET /api/run` | ✓ (модель — только пресет) | ✓ | ✓ |
| `GET /api/strategies`, `GET /api/data`, `POST /api/feedback/run` | 403 | ✓ | ✓ |
| `POST /api/data/campaign_results` | 403 | ✓ | ✓ |
| `POST /api/data/{базовая выгрузка}` | 403 | 403 | ✓ |
| `/api/lab/*` | 403 | 403 | ✓ |

Без cookie любой маршрут `/api/*` (кроме login и Swagger) отвечает 401. Зависимость роли (`ANY`/`ANALYST`/`ADMIN`)
срабатывает до тела обработчика, поэтому запрос без прав ничего не запускает и не пишет.

**Платные вызовы LLM.** `model` в `/api/run` проходит pattern `^[\w.\-/:]+$` (≤100 символов) и уходит только в
тело запроса к OpenRouter, не в URL. Manager может выбрать только модель из `MODELS`, иначе 403: экран менеджера
не должен давать запускать дорогие модели за счёт ключа сервера. Analyst и admin вводят любой slug.

## Загрузка данных

`POST /api/data/{kind}` (`datasets.py`):

1. `kind` сверяется с `KINDS`, иначе 404. Путь к файлу строится только из словаря `BASE`, так что имя файла от
   пользователя в путь не попадает (path traversal невозможен).
2. Читается не больше `50 МБ + 1` байта, больше → 413.
3. `validate` проверяет всё до записи: колонки, числовые поля, тарифы из справочника, сегменты, каналы, диапазон
   `lift_ratio`, для итогов кампаний `world` ∈ `mock | stress:<seed>` и `source` ∈ `campaign | pilot`.
   Любая ошибка → 422 со списком, ничего не записано.
4. Итоги кампаний идут в Postgres через ORM (`insert … on conflict do nothing`), базовые выгрузки — в `UPLOAD_DIR`
   атомарно (`tmp` → `replace`), предыдущая версия сохраняется в `UPLOAD_DIR/prev`. В `dataset_upload` пишется
   sha256 файла и кто загрузил.

## LLM: что уходит наружу

- Промпт строится только из `instruction` + safe JSON от `safe_context`: ячейки (тариф × сегмент), их размер и
  медианы полей из `LLM_FIELDS`. У ячеек меньше `K_MIN` абонентов статистики не отправляются. ID и прочие поля
  профиля не уходят никогда (`redacted_fields`).
- `llm_proxy` сверяет все ключи контекста с allowlist и отказывает до вызова, если есть лишний. Каждый вызов пишется
  в `llm_audit` (промпт, его хэш, ответ, ошибка), его видно на вкладке «Приватность».
- Ответ модели — недоверенные данные. `_parse_llm` принимает только существующие ячейки и тарифы, клипует оценку
  до `±LLM_CLIP`, ограничивает число гипотез на ячейку. Remediation-ответ в лаборатории проходит тот же
  `lab.validate`, что и ручные правки. Prompt injection в ответе не может выйти за эти рамки.
- Адрес API берётся только из env (`OPENAI_BASE_URL` / OpenRouter), от пользователя он не зависит (нет SSRF).

## Лаборатория

- Менять можно только ключи из `PATCH_TARGETS`: числа клипуются в границы, `choice` — из списка, строка
  `LLM_PROMPT_EXTRA` обрезается до 500 символов, переводы строк убираются. Чужой ключ → 400.
- `promote` переписывает константы в `agent.py` литералами (`json.dumps` для строк, `repr` для чисел) и проверяет
  round-trip через `ast.literal_eval`. Строку с кавычками, `#` и `\r` вырваться из литерала и выполниться не
  может, это проверено тестом. `make_submission.py` запускается без ключей LLM.
- Несуществующая версия в evaluate/remediate/promote → 404, в очередь ничего не ставится.

## Прочее

- **SQL.** Только SQLAlchemy ORM и параметризованные запросы. Единственный `text(f"...")` — имя схемы из env,
  проверенное `\w+`.
- **Фронт.** Нет `dangerouslySetInnerHTML` и `eval`, всё выводится через React (экранирование). CORS не
  включён: API принимает cookie только с того же origin. SameSite=Lax не даёт чужому сайту отправить POST с cookie.
- **Секреты.** `.env` в `.gitignore` и `.dockerignore`, в истории git ключей нет.
- **Зависимости.** На момент аудита `npm audit` — 0, `pip-audit` по зависимостям образа — 0. Локальное окружение
  со starlette < 1.3.1 уязвимо (Host header, лимиты форм): `pip install -U fastapi starlette anyio`.

## Известные ограничения

| Что | Почему оставлено | Когда чинить |
|---|---|---|
| Лимит входа в памяти процесса, ключ — IP | один воркер uvicorn | за прокси — брать IP из `X-Forwarded-For` доверенного прокси; несколько воркеров — Redis |
| `cookie_secure=False` | стенд по http | при HTTPS — `True` в `auth.py` |
| Любой вошедший может гонять `/api/run` с новыми seed (CPU) | кэш на 64 прогона, роли не анонимны | rate limit на обратном прокси |
| Нет CSP | Swagger UI грузит скрипты с CDN | при выкладке — CSP на прокси |
| Контейнер от root | `promote` пишет `agent.py` внутри образа | вынести версии агента из кода в БД |
| Swagger (`/api/docs`) открыт без входа | описание API не секрет, данные закрыты | выключить `docs_url` на выкладке |

## Перед выкладкой

1. В `.env`: `AUTH_DEMO=0`, свои `AUTH_USERS` и `AUTH_SECRET`. Если демо-пользователи уже заведены — смените
   пароли через `python3 auth.py add …` или очистите таблицу `user`.
2. Сменить пароль Postgres в `docker-compose.yml` (`POSTGRES_PASSWORD` и `DATABASE_URL`).
3. HTTPS на прокси + `cookie_secure=True`.
4. `docker compose up -d --build`, затем `python3 security_check.py`.

## security_check.py

Поднимает приложение через `TestClient` на схеме `sec_test` (удаляется в конце), LLM выключен, демо-пользователи
заводятся. Нужен запущенный Postgres (`docker compose up -d db`).

```bash
python3 security_check.py
```

Что проверяет (33 проверки, exit 1 при любом провале):

1. Все маршруты из `openapi.json` без cookie → 401.
2. Матрица роль × маршрут: у роли без прав везде 403; admin видит маршруты лаборатории.
3. Поддельный cookie и cookie после logout → 401; неизвестный email → 400, как неверный пароль.
4. 30 попыток перебора → появляется 429.
5. Загрузка: мусор, пустой файл, длинные `world`/`source`, формула, `../`, базовая выгрузка от analyst,
   50 МБ + 1 → 4xx, не 500.
6. `/api/run`: недопустимые `model`/`world`/`seed` → 422, чужая модель от manager → 403, огромный seed не роняет сервер.
7. Лаборатория: чужие ключи → 400, несуществующая версия → 404, `LLM_PROMPT_EXTRA` не выходит из литерала.
8. Заголовки `X-Frame-Options` и `X-Content-Type-Options`.
9. Пустая таблица пользователей без `AUTH_USERS` и `AUTH_DEMO` → `bootstrap` падает, демо-паролей нет.
